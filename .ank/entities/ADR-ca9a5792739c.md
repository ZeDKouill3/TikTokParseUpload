## Contexte
Les gros succès TikTok de l'utilisateur (40 k vues) sont venus de clips sur des
sujets au pic de hype (Hytale à sa sortie, un streamer à son pic) ; la hype
TikTok vient de Twitch et YouTube (research/tiktok-tips.md §10, « effet
actualité »). Aujourd'hui Clipper ne sait que surveiller les VOD d'une chaîne
donnée (clipper/watch.py, SPEC-74e9 §5). L'utilisateur veut une « Veille » qui
lui propose chaque jour 2-3 VOD à clipper, choisies par Claude d'après des
chiffres officiels et ses goûts, et qui ne garde pour la publication que les
meilleurs clips du jour. Réponses de l'utilisateur recueillies le 2026-10-06
(research/cloud/veille-plan.txt, local) ; planification faite sans lui pour le
reste, hypothèses listées en fin de document.

## Décision
1. **Bibliothèque, pas une étape.** `clipper/veille.py` est une bibliothèque
   au sens d'ADR-35b7 (comme `watch.py`) : elle n'écrit rien sous
   `workspace/<video_id>/`, n'importe jamais `clipper.web` ni une étape, et
   met une VOD en file par `clipper.worker.enqueue` uniquement. Ses réglages
   vivent dans son `CONFIG_DEFAULTS` (table `[veille]` de `config.toml`).
2. **Sources officielles seulement, collecteurs injectés.** Trois sources :
   Twitch Helix (streams FR par jeu, top jeux, VOD par jeu), YouTube Data API
   v3 (`videos.list chart=mostPopular regionCode=FR videoCategoryId=20`, 1
   unité par appel, jamais `search.list`), Steam Web API
   (`ISteamUserStats/GetNumberOfCurrentPlayers`, `ISteamChartsService/
   GetMostPlayedGames`, `ISteamApps/GetAppList` pour les noms). Jamais de
   scraping (SteamDB l'interdit), jamais TikTok (pas d'API de tendances).
   Chaque collecteur est injectable (`collectors={...}`) et le transport HTTP
   aussi : aucun test ne touche le réseau.
3. **Tout en fichiers sous `state/veille/`** (ADR-35b7 §3, écriture atomique) :
   relevé quotidien par jour (`history/<date>.json`), état du jour
   (`days/<date>.json` : sources, jeux, candidats, propositions), VOD déjà
   proposées (`seen.json`), sélection des clips (`selection/<date>.json`),
   demande de rafraîchissement (`refresh.json`), jeton d'app Twitch en cache
   (`twitch_token.json`). Lisible sans le serveur ; rétention `history_days`.
4. **Claude décide, une fois par relevé.** Un appel texte seul à
   `clipper.llm.ask("veille", ...)` (ADR-b1c1, usage `veille`, modèle
   `strong`), schéma JSON `{picks: [{candidate_id, reason}], skipped_note}`,
   contrôle `check` (ids existants, uniques, ≤ `max_vods_per_day`). Le
   prompt porte les candidats chiffrés (vues, viewers FR et joueurs Steam
   aujourd'hui vs moyenne 7 jours) et les goûts de l'utilisateur (`taste`,
   texte libre). Pas de liste de streamers. Zéro proposition est une réponse
   valide (avec sa raison), jamais une proposition inventée (ADR-ad2e).
5. **Le worker exécute, le web affiche.** Relevé quotidien (`run_at`,
   Europe/Paris), « Rafraîchir », choix Claude et sélection des clips
   tournent dans le processus worker (ADR-35b7 §1). `clipper/web` lit les
   fichiers d'état, dépose des demandes (refresh, Clipper, Ignorer,
   Restaurer) et n'appelle ni une API externe ni un LLM (ADR-09ad).
6. **Erreur par source, visible, jamais bloquante pour les autres.** Clé
   absente, HTTP non 2xx, réponse illisible : `sources.<source>.status =
   "error"` avec un message en français nommant la cause (et le réglage à
   remplir), les autres sources et le choix Claude continuent avec ce qu'il
   y a. Aucun chiffre inventé : une donnée absente est `null` avec sa raison
   (« clé absente », « hors Steam », « pas assez d'historique »).
7. **Meilleurs clips du jour, archivage réversible.** Parmi les clips des VOD
   venues de la veille et terminées le même jour (Europe/Paris), les
   `best_clips_per_day` meilleurs par `score` du sidecar (QA passée) sont
   gardés ; les autres sont **archivés** : masqués de l'écran Clips, jamais
   supprimés ni modifiés, « Restaurer » les ramène. Un clip déjà approuvé,
   programmé ou publié n'est jamais archivé. Recalcul à chaque VOD de veille
   terminée.
8. **Clés.** `twitch_client_id`, `twitch_client_secret`, `youtube_api_key`
   dans `[veille]` de `config.toml` (fichier ignoré par git, même traitement
   que `[web] token` : jamais renvoyées par `/api/settings`, masquées par
   `clipper.journal`), saisies dans Réglages › Veille. Steam n'en demande pas
   pour ces appels (documentation officielle : `GetNumberOfCurrentPlayers`
   sans clé). Une source sans clé = erreur visible (point 6), pas une veille
   arrêtée.

## Conséquences
- Nouveau module `clipper/veille.py` (+ `clipper/veille_sources.py` pour les
  collecteurs réels), nouveaux fichiers `state/veille/`, nouvelle section
  `[veille]`, usage LLM `veille`, hook dans la boucle du worker, routes
  `/api/veille/...`, écran « Veille », champ `veille` sur la vue d'un clip,
  filtre « archivés » sur l'écran Clips, section Réglages › Veille.
- Coût : un appel Claude `strong` par relevé (texte court), quelques
  dizaines de requêtes HTTP par jour (quota YouTube : 1 unité). `enabled`
  est `false` par défaut : rien ne tourne ni ne coûte sans l'activer.
- Tests : collecteurs et transport injectés, `FakeBackend` pour Claude,
  `tmp_path` pour `state/` ; aucun réseau par défaut, un test réel optionnel
  derrière `CLIPPER_REAL_NETWORK=1`.
- Rapport research/tiktok-tips.md : « enregistrer le sujet de chaque clip »
  devient possible (le jour de veille et le jeu sont dans l'état).

## Hypothèses tranchées sans l'utilisateur (à confirmer ou amender)
- `enabled = false` par défaut ; activation dans Réglages › Veille.
- Clés dans `config.toml` `[veille]` (comme le jeton web), pas dans le coffre
  keyring des comptes.
- Steam : `GetMostPlayedGames` n'est pas décrit sur les pages de doc que j'ai
  pu lire (seul `GetNumberOfCurrentPlayers` l'est, sans clé) ; s'il refuse,
  la source Steam est en erreur explicite. Pas d'appel « sorties récentes »
  dédié : une sortie se voit comme un jeu qui entre dans le top sans
  historique. Correspondance jeu Twitch ↔ app Steam par nom normalisé via
  `GetAppList` ; sans correspondance : « hors Steam », jamais 0.
- Twitch : viewers FR par jeu = somme de `Get Streams language=fr` ; VOD
  candidates = `Get Videos game_id=<top jeux FR> language=fr period=day
  sort=views type=archive`. Jeton d'app (client credentials) mis en cache.
- YouTube : seules les vidéos ≥ `youtube_min_duration_s` sont candidates
  (un Short ne se clippe pas) ; signal = vues par heure depuis publication.
- « Déjà clippée » = `video_id` présent dans `workspace/`, dans la file ou
  dans `seen.json` (proposée puis mise en file ou ignorée).
- « Rafraîchir » dépose une demande que le worker exécute dans les secondes
  qui suivent (SSE `veille` pour l'affichage).
- Mobile : l'onglet « Veille » remplace « Vidéos » dans la barre basse
  (Vidéos reste dans le menu).
- En mode `auto`, les clips gardés suivent le flux auto habituel ; les
  archivés ne sont jamais approuvés automatiquement.
