## Objet
Un écran « Comptes » de la console pour noter les comptes des plateformes (TikTok, YouTube, e-mail...) : libellé, plateforme, e-mail ou identifiant, mot de passe, notes ; avec boutons Copier et un générateur de mot de passe. Pense-bête local d'un seul utilisateur sur son PC, pas un gestionnaire de mots de passe partagé.

## Règles
R1. Stockage. Les mots de passe ne sont JAMAIS écrits dans un fichier du projet ni dans un fichier en clair : ils vont dans le coffre de l'OS via la bibliothèque keyring (Gestionnaire d'identification Windows ; nom de service « clipper-accounts », clé = id du compte). Le reste (id, libellé, plateforme, identifiant, notes, dates) vit dans state/accounts.json (state/ est ignoré par git), écrit atomiquement (tmp + replace). Module clipper/accounts.py, réglages dans son CONFIG_DEFAULTS.
R2. Aucun repli silencieux (ADR-ad2e). Si keyring n'a pas de coffre sûr (backend fail/null/chiffrement en clair), l'écriture d'un mot de passe échoue avec une erreur explicite en français ; jamais de repli vers un fichier, une variable ou la mémoire.
R3. Accès depuis le PC seulement. Toutes les routes /api/accounts* refusent (403, message explicite) toute requête dont l'adresse cliente n'est pas de bouclage OU dont l'en-tête Host n'est pas 127.0.0.1/localhost[:port] (anti DNS rebinding), même avec un jeton valide. L'écran l'annonce quand la console est ouverte à distance.
R4. Exposition minimale. La liste ne renvoie jamais les mots de passe (champ has_password seulement) ; le mot de passe d'un compte ne sort que par une route dédiée appelée au clic (Afficher ou Copier). Aucun mot de passe dans un journal, events.jsonl, le flux SSE, un message d'erreur ou une trace. Aucune réponse /api/accounts* ne porte d'en-tête CORS ; les écritures exigent un corps JSON (requête non simple, préflight refusé).
R5. Générateur. Côté serveur avec secrets (CSPRNG) : longueur réglable 12 à 64 (défaut 20, CONFIG_DEFAULTS), classes minuscules/majuscules/chiffres toujours, symboles optionnels, au moins un caractère de chaque classe choisie, sans caractères ambigus en option. Le mot de passe généré peut remplir le formulaire d'un compte ou être seulement copié.
R6. Interface. Écran Comptes dans la section Configuration : liste (plateforme, libellé, identifiant, mot de passe masqué ••••), boutons Copier identifiant / Copier mot de passe / Afficher (masqué à nouveau après 30 s), Ajouter, Modifier, Supprimer avec confirmation (supprime aussi l'entrée du coffre). Copie via navigator.clipboard, retour visuel « Copié ». Jamais de nom réel de personne ou de chaîne dans le code, les tests ou la doc (exemple « ma_chaine », « exemple@example.com »).
R7. Tests. Aucun test ne touche le vrai coffre : un backend keyring en mémoire est branché dans les tests ; un test prouve le refus quand le backend n'est pas sûr, un autre que la liste et les erreurs ne contiennent jamais le mot de passe, un autre le refus hors bouclage et sur Host étranger.
