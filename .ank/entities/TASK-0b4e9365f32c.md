## Constat réel (2026-10-03, compte YouTube 670ca85bf1f0, Chrome lancé par clipper.browser)
Publication YouTube en échec : « page inattendue : https://studio.youtube.com/channel/UC... ». Cause reproduite (research/youtube-inspect/yt_probe.py) : `page.goto(urls.upload)` (https://studio.youtube.com/channel/<UC>/videos/upload?d=ud) est REDIRIGÉ vers le tableau de bord `studio.youtube.com/channel/<UC>` ; aucun champ fichier pendant 12 s. Le test `upload_url_marker` échoue donc toujours.

## Chemin qui marche (relevé réel, research/youtube-inspect/yt_probe2.py)
Studio ouvert sur la chaîne -> bouton de rôle `button` nom accessible « Créer » (banner) -> clic -> menu : `menuitem` « Importer des vidéos » (autres : « Passer au direct », « Nouvelle playlist », « Nouveau podcast ») -> clic -> la dialog d'envoi s'ouvre : `input[type=file]` présent (1) et bouton « Sélectionner des fichiers » présent, en < 1 s. L'URL NE change PAS (reste /channel/<UC>).

## À faire (clipper/youtube.py run() + clipper/assets/youtube_selectors.toml + tests)
- run() : aller sur urls.studio (comme verify), garder guard()/close_popups(), cliquer « Créer », puis le menuitem « Importer des vidéos », attendre input[type=file] attaché ; plus de goto(urls.upload) ni de contrôle `upload_url_marker` (retirer ces deux clés du toml et de la validation `need(...)`, ou les garder documentées « redirigé, ne pas utiliser » : préférer retirer). Dialog absente après le délai = stop unexpected_page explicite.
- toml : labels `create = "Créer"`, `upload_menu = "Importer des vidéos"` ; sélecteurs par rôle ARIA ou CSS équivalent ; marquer « vérifié 2026-10-03 (Chrome piloté) ».
- Tests (FakePage de tests/test_youtube.py) : le flux passe par Créer -> Importer des vidéos avant set_input_files ; menu sans « Importer des vidéos » -> stop explicite ; plus aucun goto vers /videos/upload. Adapter les tests existants qui supposaient l'URL d'envoi.
