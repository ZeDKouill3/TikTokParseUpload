## Pourquoi
Les gros succès TikTok de l'utilisateur sont tous tombés de J+3 à J+15 après
la sortie d'Hytale : la veille doit savoir quels jeux viennent de sortir et
lesquels arrivent. Règles : SPEC IGDB (R11 à R16), sur ADR-798c (IGDB admis
comme source, même jeton Twitch) ; SPEC-bdd9 reste en vigueur.

## Périmètre
- `clipper/veille_sources.py` : collecteur `igdb` (R12) réutilisant le jeton
  de `_Twitch` et son cache ; le collecteur Twitch rend en plus `igdb_id`
  (chaîne, vide si Twitch ne l'a pas) pour les jeux de `helix/games/top`.
- `clipper/veille.py` : réglages R11 dans `CONFIG_DEFAULTS` (validation
  comme R1), `igdb` dans `SOURCES` et `_REQUIRED_KEYS` (clés Twitch),
  `releases` du jour (R13), `release` sur les jeux et
  `signals.release_days_since` sur les candidats (R14), prompt (R15).
- Tests sans réseau (R16) dans `tests/test_veille.py` et
  `tests/test_veille_sources.py`, test réel optionnel derrière
  `CLIPPER_REAL_NETWORK=1`.
- Hors périmètre : écran, routes, réglages web, GUIDE, CHANGELOG (tâche
  suivante). `clipper/web` ne change pas ici ; `GET /api/veille` rend déjà
  l'état du jour entier, donc `releases` passera sans code web.
