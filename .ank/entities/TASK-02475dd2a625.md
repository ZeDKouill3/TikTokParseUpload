Retour utilisateur 2026-10-02 (console web).

## 1. Bug : post publié via Clipper sur un 2e compte TikTok absent de l'écran Publication
L'utilisateur a créé un 2e compte TikTok dans Comptes (label « clippyqaniaque »), y a publié un clip depuis l'écran Publication (« Nouvelle publication », compte = ce 2e compte, carte affichée « sans chaîne ») ; la publication a réussi sur TikTok mais n'apparaît pas dans l'écran Publication. Cause probable : la vue filtre par chaîne (`GET /api/publish?channel=&week=`, `clipper/web/static/screens/publish.js`) et un post dont le clip n'est lié à aucune chaîne, ou dont le compte n'est lié à aucune chaîne, tombe hors de toutes les vues. Trouver la cause, test de non-régression.

## 2. Publication et Statistiques triées par COMPTE TikTok, plus par chaîne
- Écran Publication : le sélecteur en haut devient le compte TikTok (« Tous les comptes » + chaque compte de Comptes) ; calendrier, liste des publiées / échecs filtrés par compte de publication, pas par chaîne. Tout post publié ou programmé via Clipper apparaît sous son compte.
- Écran Statistiques : déjà par compte TikTok (SPEC-47e2 R3) ; retirer toute dépendance ou mention de chaîne qui filtrerait ou masquerait un compte non lié à une chaîne.

## 3. Renommer « Chaîne » en « Style » partout dans ce que l'utilisateur voit
Une « chaîne » n'est qu'un preset de rendu/sélection (presets/<nom>.toml). Dans la console : menu, titres d'écran, libellés, boutons, messages, info-bulles, « sans chaîne » -> « sans style », « Chaînes » -> « Styles » ; aussi README et docs/ utilisateur (pas les entités .ank). Les identifiants internes (dossier presets/, table [channel], routes /api/channels, noms Python/JS) restent inchangés pour ne rien casser ; l'URL #/chaines peut devenir #/styles avec redirection de l'ancienne.
